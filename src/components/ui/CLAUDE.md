# Shared UI components

New UI must use these primitives — do not hand-roll raw Tailwind for cards, buttons, badges, or table cells. Global UI conventions (mobile-first/touch, pill view-switchers, 12-hour time display) are in root `CLAUDE.md`'s UI Conventions section.

- `<Card href? className?>` (`Card.tsx`) — browseable item collections (horses, upcoming lessons, members). With `href` it renders as a full-card link with `bg-white`/hover states baked in; without `href` it renders a plain bordered `div` with no background or padding of its own — pass `className` for either variant's padding/spacing needs.
- `<Button variant? size? loading? href?>` (`Button.tsx`) — all interactive actions. Variants: `primary` (default), `secondary` for a de-prioritised action (Edit, Cancel, Copy, Close), `danger` for destructive actions, `warning` for amber attention-badge links (dashboard Reminders cards, `DocumentRemindersSection`'s entries). `size`: `md` (default) for standalone form/page actions, `sm` for compact table/row actions. `loading` disables the button and shows a spinner. With `href` it renders as a styled `Link` instead of a `<button>`. Icon-only/bare-text controls are poor structural fits — leave those as raw Tailwind with a comment explaining why (see `LessonForm.tsx`'s Normal/Group switch or `NotificationBell.tsx`).
  - **No unfilled variant, and never a variant swap to show state.** #1548 deleted `ghost`, which was both, and each half failed: outlined-enabled was indistinguishable from `disabled:opacity-50`, and as an off state the fill was the only differentiator. Every variant now declares its own `disabled:` pair, enumerated in `Button.test.tsx`.
  - **The state idiom follows what the control is:** on/off committing on tap → `<Switch>`; one of a few values committing on tap in a table row → a joined group of these (`role="group"`, current `primary` and the rest `secondary`, `aria-pressed` each, corners squared via `className` — `HorseAccessSection.tsx`'s Documents); form mode in client state, committed by Save → raw-Tailwind segmented control (`HorseManagerForm.tsx`'s status); view switcher → `<Pill>`; a field Save commits later → native checkbox.
- `<Switch checked label>` (`Switch.tsx`) — a `<button type="submit" role="switch" aria-checked>` not a checkbox, so it submits pre-hydration inside `<form action={boundAction}>` (#1390). `label` names the control, never the state. No `className`, for `Badge`'s reason.
- When matching an icon-only/bare-text raw-Tailwind control to a sibling elsewhere in the app, reuse that control's exact classes **and its exact glyph** — divergent one-off styling for one interaction pattern is a recurring review finding, and the glyph is not cosmetic. For the date/month Prev-Next pagers that means importing `dateNavButtonClass` (`date-nav.ts`) and never restating the string; that module's own comment carries the rest — its three call sites, the glyph rule, and the hand-kept copies that had already drifted when #1394 collapsed them.
- `<Th>` / `<Td tone?>` / `<TableActions>` (`Table.tsx`) — all data tables. Use `tone="secondary"` on `<Td>` for secondary text cells. `<TableActions>` is a right-aligned `<Td>` for row action buttons.
- `<AccordionSection title hint? defaultOpen? slug? savedSlug? openSlug? headerExtra?>` (`AccordionSection.tsx`) — a collapsed-by-default card section, built on native `<details>` so it works before hydration. Used by Manage Barn (every section is configuration) and the horse detail page (an always-visible identity header, then these). `hint` is the collapsed row's payload preview — `Documents · 2`, `Access · 1 member` — so a shut section still says whether opening it is worth a tap; a section with nothing to preview omits it. `headerExtra` renders as a positioned sibling of the `<summary>`, not inside it: a control inside a summary toggles the accordion instead of firing its own action. `slug` names the section in the page's URL (#1417): with it set, `savedSlug` (from `?saved=`) reopens the section *and* badges it `Saved`, `openSlug` (from `?open=`) reopens it silently — how Manage Barn survives the `redirect()` every save action ends in. Both comparisons are guarded on `slug` being set, so a slugless section can't match an absent param and open itself.
- `<Pill href active>` (`Pill.tsx`) — tab-pill view switchers. Always renders as a `Link`; `active` selects the filled vs. outlined style.
- `<Badge tone>` (`Badge.tsx`) — all status badges. Tones: `amber` (attention/unpaid/inactive), `red` (cancelled), `green`, `gray` (neutral metadata: Recurring/Jumping/Group, and the Lesson Tiers **Default** marker). Never hand-roll a `rounded-full px-2 py-0.5` span — declaring badge colours per call site is what let a 2.15:1 `bg-amber-500`/`text-white` pair exist at seven sites (#1219). `Badge` takes no `className`: a per-call-site styling escape hatch reopens exactly that. Wrap it (`<div className="mt-1">`) for spacing instead. Every tone is asserted at ≥4.5:1 in both schemes by `Badge.test.tsx`, which reads Tailwind's real palette — a new tone below the floor fails that test.

Placement rules:
- "Add" / "Create" buttons go top-right of the section header, next to the section title — never at the bottom of a section.
- Row actions always go in the rightmost table column (use `<TableActions>`), never in the first column or mixed with data columns.
