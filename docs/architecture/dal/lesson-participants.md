# `lesson-participants.ts`

Participant management: `createLessonWithParticipants`, `updateLessonWithParticipants`, `updateLessonRiderNotes` (writes `lesson_riders.rider_notes`/`private_notes` via the `update_lesson_rider_notes` RPC rather than a direct table update — see [`rpc/lessons.md`](../rpc/lessons.md) — since a bare `.update().select()` would trip an implicit `RETURNING *` the caller no longer has `SELECT` privilege for;
returns `void`, not the updated row), `updateLessonHorseNotes` (#1082 — same defect, same reason: writes `lesson_horses.horse_notes` with a direct `.update()` and deliberately no `.select()`, since a bare `.select()` trips the implicit `RETURNING *` against `exertion_level`, which is outside the column-restricted SELECT grant;
needs no RPC unlike its rider counterpart, because `UPDATE` on `lesson_horses` is still table-wide granted and all three WHERE columns sit inside the granted SELECT list;
returns `void`);
`getRiderEnrolledLessonIds(barnId, userId, client?)` — resolves active rider membership then returns enrolled lesson IDs;
`cancelRiderParticipation(lessonId, barnId, riderId, notes?, isLate)` — cancels a single rider's participation via the `cancel_rider_participation` RPC;
sets `lesson_riders.cancelled_at=now()` and `cancellation_notes` (not `rider_notes`, which cancellation no longer touches);
zeroes `lessons.fee` only when `isLate` is `false` (#885 — the RPC stopped also nulling `payment_type`, that column no longer exists);
returns `boolean` — whether this call cascaded the whole lesson to cancelled (see the RPC's own doc entry in [`rpc/lessons.md`](../rpc/lessons.md)) — so `cancelRiderParticipationAction` knows whether to also fire a `lesson_cancelled` notification.
Neither `createLessonWithParticipants` nor `updateLessonWithParticipants` takes an `instructorCut` or passes `p_instructor_cut` — #1154 deleted that chain (a #776 leftover, forwarded but ignored all the way to the RPC), since `lessons.instructor_cut` is derived server-side; the RPC signatures still carry the parameter, for the reason recorded in [`rpc/lessons.md`](../rpc/lessons.md).
`updateCancellationFeePaymentType(lessonRiderId, barnId, paymentType)` (#831) — manager-only mark-paid/revert for a `rider_cancellation_fee` transaction, calling the `collect_rider_cancellation_fee` RPC; used by `updateCancellationFeePaymentTypeAction` (`src/app/actions/lessons.ts`), wired into `OutstandingTable`'s payment-type dropdown for a `cancellation_fee` row; `hydrateParticipants` sorts its horse and rider participants alphabetically by resolved name (#1286) — on the participant objects, so `horse_ids`/`rider_ids`/`rider_cancelled_ats` stay positionally aligned with `horse_names`/`rider_names`
