# `member-horse-privileges.ts`

Manager-only CRUD for `member_horse_privileges` (#998, foundation from #997) — `getHorsePrivileges(horseId, barnId)` lists a horse's grants;
`grantHorsePrivilege(horseId, barnId, memberId)` inserts a row with column defaults (`document_privileges='none'`, `lesson_read_privileges=false`) — the horse detail page's Access section then flips these individually;
`updateHorsePrivilegeDocumentAccess(privilegeId, barnId, value)`/`updateHorsePrivilegeLessonAccess(privilegeId, barnId, value)` — single-column updates, one per toggle (mirrors `barn-memberships.ts`'s `setCanInstruct` single-flag idiom rather than one combined upsert, since the document-access buttons and lesson toggle fire independently in the UI);
`revokeHorsePrivilege(privilegeId, barnId)` calls the `revoke_horse_privilege` RPC (#998 redesign — the horse detail page's Access table now also doubles as the owner picker, so revoking a grant must atomically clear `horses.owning_member_id` if that member was the current owner;
the module's direct table access (`getHorsePrivileges`, `grantHorsePrivilege`, `updateHorsePrivilegeDocumentAccess`, `updateHorsePrivilegeLessonAccess`) still needs no RPC, since `member_horse_privileges`' `manager_all_member_horse_privileges` RLS policy is already `FOR ALL` — a true universal when #998 wrote it, before `setHorseOwner` (#1069) and the two #999 RPC-relayed reads below joined the module);
`setHorseOwner(horseId, barnId, memberId)` (#1069, revised to close a non-atomic-write review follow-up) calls the `set_horse_owner` RPC — the forward-direction counterpart to `revokeHorsePrivilege`'s owner-clearing — atomically setting `horses.owning_member_id` and, when `memberId` is non-null, elevating that member's `member_horse_privileges` row (`document_privileges='write'`, `lesson_read_privileges=true`) in the same statement;
a `null` `memberId` only clears ownership, no privilege row to elevate.
Replaces the original two-call version (`updateHorseDetails` + a since-removed `elevateOwnerPrivileges`), which could leave a horse owned with privileges never elevated if the second call failed.
**#999 additions**: `getMyHorseDocumentPrivilege(horseId, barnId)`/`getMyHorseLessonReadPrivilege(horseId, barnId)` — thin wrappers around the `auth_get_horse_document_privilege`/`auth_has_horse_lesson_read_privilege` `SECURITY DEFINER` RPCs (already `GRANT EXECUTE`d to `authenticated` for RLS's own use since #997), letting a rider caller look up their own privilege for a horse directly — `member_horse_privileges` itself has no rider-facing RLS grant, so a plain `SELECT` isn't an option the way it is for `getHorsePrivileges`' manager-only callers; used by the horse detail page to gate its Documents/Exhaustion/Upcoming-Lessons sections.
`getHorsePrivileges` stays unordered (#1286): `member_horse_privileges` carries only `member_id`, so the Access table's alphabetical order is applied by the horse detail page, after it resolves the names.
