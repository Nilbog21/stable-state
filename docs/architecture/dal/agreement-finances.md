# `agreement-finances.ts`

Ledger-backed agreement-charge financial reporting — income fold-ins consumed by `lesson-finances.ts`, plus the Outstanding charges read — split out of `agreements.ts`, which keeps the agreement/charge record CRUD; completes the `lessons.ts`/`lesson-finances.ts` and `expenses.ts`/`expense-finances.ts` CRUD-vs-finances seam for the third revenue domain.
Also exports `CHARGE_TRANSACTION_KINDS` (the `lease_charge`/`board_charge` kind pair), imported back by `agreements.ts`'s two record-surface ledger reads (`getChargesForAgreement`, `getUnpaidAgreementIds`): `getChargesForSummary(barnId, startDate, endDate, client?)`
(#828, #865 — now calls `transactions.ts:getTransactionRows` with `kind IN ('lease_charge','board_charge')` instead of embedding the query directly, mapping `occurredAt`→`period`/`amount`→`fee`; same external `{period, fee, payment_type}[]` shape as before, so `lesson-finances.ts` needed no changes.
**#1309 note**: that `occurredAt.slice(0, 10)` is *correct* and carries a comment saying so — a charge transaction's `occurred_at` is not a real instant, it's the `period` DATE laundered through `v_period::timestamptz` by `create_agreement_with_first_charge`/`generate_agreement_charge`, landing at exact UTC midnight on the 1st, so slicing the UTC date back out recovers exactly the DATE that went in.
Replacing it with `barnDay(...)` would shift every charge to the last day of the previous month, for every barn, always; and `getTransactionRows`'s `.gte`/`.lt` window needs no padding here for the same reason — a charge sits exactly on its month's `startDate` and membership is correct *because* both sides are UTC, the opposite of the `expense-finances.ts` `QUERY_PADDING_MS` situation.
Unlike `getPaidCharges` below, this reader has no `agreement_charges` round-trip to read the real column off, and adding one for a barn-wide summary fold isn't worth the query), `getPaidCharges(barnId, startDate, endDate, client?)`
(#828, #865 — calls `getTransactionRows` with the same kind filter plus `collected: true`;
`kind`/`membershipId`/`horseId` are already on the returned row, so `agreementId` and — as of #1309 — `period` are resolved via a small follow-up `agreement_charges` lookup keyed by the distinct non-null `agreementChargeId`s returned (a null id, defensive-only since no code path currently hard-deletes an `agreement_charges` row, skips the lookup and falls back to the transaction's own id and to `occurredAt.slice(0, 10)` respectively), replacing the former FK-hint-pinned embed;
that select is `'id, agreement_id, period'` rather than `'id, agreement_id'` (#1309) — the round-trip already existed for `agreement_id`, so reading `period` off the real column costs no extra query, and it removes the trap that produced #1309, where re-deriving `period` from `occurred_at` read like a real-instant decode a later reader would "fix" into `barnDay(...)`;
`PaidCharge.riderId`/`horseId` are `string | null` (#865 — a rider's `membership_id` can be nulled by `ON DELETE SET NULL` when their membership is removed after a charge is already collected;
`lesson-finances.ts`'s `getHorseIncomeSummary`/`getRiderIncomeSummary` fold a null into the same `NO_HORSE_LABEL`/`NO_RIDER_LABEL` bucket a lesson with no junction rows already falls into, rather than corrupting the grouping map with a literal `null` key)), `getOutstandingCharges(barnId, timezone, userId?, role?, client?)`
(#831 — candidate unpaid-looking charges with `period` before the first of the current month **in the barn's own zone** (#1309 — `firstOfMonth(barnToday(timezone))`, replacing a `Date.UTC(now.getUTCFullYear(), now.getUTCMonth(), 1)` that bucketed by the server host's month; every zone in `BARN_TIMEZONES` is behind UTC, so the host's month rolled over 4–10 hours early and the Outstanding page and dashboard briefly showed the still-current month's lease/board charges as overdue.
`timezone` sits second rather than last because the three arguments after it are optional — same placement as `expenses.ts:getOutstandingExpenses`, the other outstanding read needing the barn's zone; threaded from all four call sites, the three pages plus `scripts/generate-outstanding-notifications.ts`'s nightly cron, whose `barns` select already carried `timezone` for its `getOutstandingExpenses` call.
The eslint fence didn't catch the original because these were `getUTC*` reads, not the banned host-zone getters — reading UTC is only wrong here because the value is then compared against a barn-local calendar day), resolved to `kind`/`riderName` via a single-round-trip FK-hint embed as before — `getAgreementsMapForCharges`'s two-query join was deleted (#707); `role==='trainer'` short-circuits to `[]` since trainers aren't parties to agreements; `role==='rider'` first resolves the caller's own agreement IDs, then filters charges to those — but since `agreement_charges.payment_type` is gone, a candidate is only kept once `transactions.ts:getOutstandingTransactionRows` relays its `lease_charge`/`board_charge` transaction back as `collected=false`, same relay RPC `getOutstandingLessonRows` uses)
