# `notifications.ts`

Notification CRUD: `createNotification` (upserts on `user_id,barn_id,type`; resets `read_at` on conflict); `upsertNotification(client: SupabaseClient, params)` (required-client, no-fallback variant — needed because service-role callers have no `auth.uid()` to satisfy `create_or_update_notification`'s RLS-gated RPC — upserts directly against the table on the same `user_id,barn_id,type` conflict target, bypassing `create_or_update_notification`'s RPC for service-role callers whose `auth.uid()` is null; shared by `generate-recurring-lessons.ts` and `generate-outstanding-notifications.ts`); `deleteNotificationByType(userId, barnId, type, client?)`
(deletes a notification by user+barn+type; no-op if not found); `upsertNotificationsForRecipients<T>(client, recipients, formatter, type, linkForBarn, send?)`
(consolidates the "aggregate recipients into a Map, then send each with an isolated try/catch" pattern shared by the nightly notification scripts and the cancellation actions — iterates `recipients: Map<string, {userId, barnId, payload: T}>`, sends one notification per entry sequentially via `send` (defaults to `upsertNotification`'s raw table upsert, for service-role script callers), and returns the count of per-recipient failures rather than throwing; used by `generate-recurring-lessons.ts` (2 calls, `payload: number`) and `generate-outstanding-notifications.ts` (1 call, `payload: {count, total}`) with the default `send`; `cancelLessonAction`/`cancelRiderParticipationAction` (`src/app/actions/lesson-cancellation.ts`) pass a `send` override backed by `createNotification`'s RPC, since their session-authenticated client can't satisfy the raw upsert's RLS-gated `ON CONFLICT DO UPDATE` for another user's row); `resolveCancellationRecipients(params)` (pure — encodes "who gets notified for a cancellation," shared by `cancelLessonAction`/`cancelRiderParticipationAction`: whole-lesson cancel by trainer → managers + riders, by manager → instructor + riders; single-rider cancel by the rider themself → instructor + managers, by trainer on the rider's behalf → affected rider + managers, by manager on the rider's behalf → affected rider only); `markAllNotificationsRead` (sets `read_at = now()` for all unread for a user in a barn); `getNotifications(userId, barnId, limit=20)` (recent notifications ordered by `created_at DESC`); `formatNearbyInstructorNotification(count)` (pure — `instructor_lesson_nearby` title/body, singular/plural by count; shared by `submitLesson` and `generate-recurring-lessons.ts`'s batched aggregation, so both produce identical copy); `getUnreadNotificationCount(client, userId, barnId, type)` (#1017 review follow-up — parses the leading integer off an existing unread row's title, or `0` if none exists/unread; `instructor_lesson_nearby` is written by both `submitLesson` (always adds 1) and `generate-recurring-lessons.ts` (adds its own per-run aggregate) to the same `user_id,barn_id,type` upsert target, so each producer reads this first and adds to it instead of blindly overwriting the other's count — the same upsert-collision class #535 fixed for `lesson_cancelled` by splitting notification types instead, not viable here since both producers legitimately share one type)
