# `document-backup.ts`

Barn-wide documents-as-zip export (#995), companion to #994's spreadsheet export.
`getAllBarnDocuments(barnId, client?)` — like `documents.ts`'s `getDueDocuments` but barn-scoped only (no `reminder_date` filter), returns `{ horse, trainer, rider }` raw rows from all three document tables.
`buildBackupZipEntries(docs, horseNames, memberNames)` — pure function, no I/O: plans each document's path in the archive as `horse/<horse name>/<file>` or `member/<member name>/<file>` (trainer + rider documents share the `member/` namespace, keyed by the shared `barn_memberships.id` via `resolveMemberNames`, since a person's role can change but their membership id doesn't); filename is `<original base>-<record_type>-<created_at date>.<ext>`, deduped with a numeric suffix on collision within the same folder; every path segment — the folder name and the filename's base and extension alike — is sanitized (`/`/`\` each replaced with `-`, not dropped) since horse/member names and uploaded filenames are free text.
`buildDocumentsBackupZip(barnId, client?)` — orchestrates `getAllBarnDocuments` + `resolveHorseNames`/`resolveMemberNames` + `buildBackupZipEntries`, downloads each document's bytes via `document-storage.ts`'s `downloadFile`, and assembles an in-memory `jszip` archive; returns `null` when the barn has zero documents (server-side enforcement of "nothing to download," independent of the UI's disabled button).
All three `getAllBarnDocuments` queries carry `.order('created_at')` (#1286) — `buildBackupZipEntries` assigns its `-1`/`-2` collision suffixes in input order, so two documents colliding on one archive filename would otherwise swap suffixes between runs.
