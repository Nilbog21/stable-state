# `documents.ts`

Unified horse/trainer/rider document CRUD, replacing the three former per-entity modules: `getDocumentsWithUrls(entity, entityId, barnId)`, `createDocument(entity, barnId, entityId, recordType, storagePath, fileName, fileSize, notes, reminderDate)`, `deleteDocument(entity, id, entityId, barnId)`, `updateDocumentReminderDate(entity, id, entityId, barnId, reminderDate)`, where `entity` is `'horse' | 'rider' | 'trainer'`.
Each function has one TS overload per entity so callers get `HorseDocument[]`/`RiderDocument[]`/`TrainerDocument[]` back with no casting, with `getDocumentsWithUrls` returning `{ doc, signedUrl }[]` pairs (each document paired with a 300s signed URL via `document-storage.ts`'s `getSignedUrl`) — consolidating the fetch-then-sign motion the horse and member detail pages previously each hand-rolled — while the raw row query (`getDocuments`) is now module-private with no exported adapter.
`entityId` is always filtered on delete (previously only the horse variant checked it; rider/trainer did not).
`reminderDate` (`YYYY-MM-DD` or `null`) is set at upload and can be pushed forward later via `updateDocumentReminderDate` — no new RLS needed, since the existing uploader INSERT policies and manager `FOR ALL` policies aren't column-restricted.
`getDueDocuments(barnId, today)` — no-cron reminder surfacing: queries all three document tables for `reminder_date <= today` (`today` passed in by the caller rather than computed internally, for testability) and returns a flat `DueDocument[]` sorted by `reminderDate` ascending.
Horse-doc owner names resolve via `resolveHorseNames` (from `horses.ts`, passed this function's own client); trainer/rider-doc `ownerId` is simply `trainer_id`/`rider_id` as stored (a `barn_memberships.id` since #738), with the owner name resolved via a single `resolveMemberNames` call (`member-names.ts`) — `'Unknown Member'` is the fallback for any id it can't resolve.
This dropped a "membership removed but profile persists" fallback path the prior auth-user-id-keyed version needed: `rider_documents`/`staff_documents` now `ON DELETE CASCADE` from `barn_memberships`, so a document can no longer outlive its owning membership.
