# `agreements.ts`

Lease/board agreement + charge CRUD: `getAgreementStatusLabel(agreement)` (pure — `is_active=false` → `'Ended'`; else `cadence='one_time'` → `'Complete'` (a one-time agreement's single charge is created at creation and never bills again), else `'Active'`; used by both the agreements list and detail pages); `createAgreement(params, client?)`
(calls `create_agreement_with_first_charge` RPC), `getAgreementsByBarn(barnId, kind?, client?)`, `getAgreementById(agreementId, barnId, client?)`, `updateAgreement(agreementId, barnId, updates: { fee? })`, `endAgreement(agreementId, barnId)` (sets `is_active=false`);
charge fns `getChargesForAgreement(agreementId, barnId)` (#885 — after the base `agreement_charges.*` select, overlays each charge's `payment_type` from a second `transactions` query, keyed on `agreement_charge_id`, `kind IN ('lease_charge','board_charge')` — `agreement_charges.payment_type` is no longer written by `mark_agreement_charge_paid`, so trusting the column directly would go stale;
both queries are already manager-only RLS, so no RPC is needed, unlike the lesson-side `get_lesson_payment_info`;
unlike `agreement-finances.ts`'s `getChargesForSummary`/`getPaidCharges`, this doesn't go through `transactions.ts:getTransactionRows` — that reader has no per-charge-ID filter, and this call only ever needs one agreement's charges, so a targeted query stays cheaper than a barn-wide fetch), `updateCharge(chargeId, barnId, fee)` (#828 — calls `update_agreement_charge_fee` RPC instead of a direct table update, so the linked `transactions.amount` stays in sync), `updateChargePaymentType(chargeId, barnId, paymentType)` (#828 — calls `mark_agreement_charge_paid` RPC instead of a direct table update, syncing the linked `transactions.collected`/`payment_type`;
no longer dual-writes `agreement_charges.payment_type` as of #885, see that RPC's own doc entry in [`rpc/agreements.md`](../rpc/agreements.md)), `generateChargeForMonth(agreementId, barnId, timezone, at, client?)`
(calls `generate_agreement_charge` RPC; atomic and barn-scoped, so it never overwrites an already-paid charge and never crosses barns.
**#1361 update**: `at` is a real instant, so the month it falls in is the *barn's* — it resolves as `firstOfMonth(barnDay(at, timezone))`, replacing a `Date.UTC(period.getUTCFullYear(), period.getUTCMonth(), 1)` truncation in the server host's frame that filed any charge generated in the last 4–10 hours of the barn's month under the next one.
`timezone` sits right after `barnId`, matching `agreement-finances.ts`'s `getOutstandingCharges(barnId, timezone, …)`; keeping the crossing inside the DAL rather than at the two script call sites is what makes it unit-testable per-zone).
**#1441**: those three wrappers (`updateCharge`, `updateChargePaymentType`, `generateChargeForMonth`) return `AgreementChargeRow`, not `AgreementCharge` — all three RPCs `RETURNS agreement_charges`, a rowtype with no `payment_type` column since #831, so the old cast promised a field the row never carries. See [`types.md`](types.md); `getChargesForAgreement` still returns full `AgreementCharge`s, since it overlays the field from `transactions` itself.
`getBarnDefaultBoardFee(barnId, client?)`; `getActiveAgreementsForRider(barnId, riderId, client?)`
(query-scoped lookup of all of a rider's active agreements, any kind, most-recently-created first — a rider can have more than one simultaneously-active agreement, e.g. boarding two horses, so this returns every match rather than assuming exactly one row exists — used by the member detail page's Active Agreements section, #772); `getUnpaidAgreementIds(barnId, timezone, client?)`
(#831 — barn-wide, manager-only caller, so this reads `transactions` directly via `getTransactionRows` instead of going through the relay RPC; resolves each unpaid charge transaction's `agreementChargeId` to an `agreement_id` via a small follow-up `agreement_charges` lookup, same idiom as `agreement-finances.ts:getPaidCharges`. Its "before the first of the current month" bound is `firstOfMonth(barnToday(timezone))` — the barn's month, not the server host's, which rolled over 4–10 hours early and briefly badged the still-current month's charge as unpaid, #1360; the same fix #1309 made to `getFinancialSummary`/`getOutstandingCharges`)
