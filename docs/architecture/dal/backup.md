# `backup.ts`

Barn-wide data spreadsheet export (#994), companion to #995's documents zip.
`getBarnBackupData(barnId, timezone, client?)` fetches and joins every covered table into 8 flat, human-readable row shapes — **Horses**, **Lessons** (+ `lesson_horses`/`lesson_riders`/`lesson_tiers`/`lesson_series` folded in as columns rather than shipped as their own sheets — junction/lookup data is denormalized onto each lesson row: joined horse/rider/instructor names via `lesson-finance-queries.ts:getLessonJunctionRows` + `member-names.ts`/`horses.ts` resolvers, a `Recurring` flag from `series_id IS NOT NULL`, a `Tier` column read straight off `lessons.tier_name` (the write-time snapshot every lesson row already carries — `lesson_tiers` itself is never queried by this module), and `Collected`/`Instructor Payout` sourced from `lesson-finance-queries.ts:getLessonFeeRows` called with wide sentinel date bounds instead of a reporting window so it returns full history), **Agreements**, **Agreement Charges** (rider/horse name and `kind` resolved via the agreement each charge belongs to;
`Collected`/`Payment Type` overlaid from `transactions.ts:getTransactionRows(barnId, CHARGE_TRANSACTION_KINDS)` keyed by `agreement_charge_id`, since `agreement_charges` itself has carried no `payment_type` column since #831 — same overlay idiom `agreement-finances.ts:getPaidCharges` already uses), **Horse Expenses** (reuses `expenses.ts:getExpensesByBarn` directly — already resolves horse names and carries its own `payment_type` column, no ledger lookup needed), **Members** (a fresh `barn_memberships` + `profiles` two-query join scoped to the barn with no `status` filter (the roster reads in `barn-memberships.ts` all carry `eq('status', 'active')`; a vacuous distinction since #1037 narrowed `MembershipStatus` to `'active'` only, but the filter's absence here is deliberate) — `barn-memberships.ts`'s `joinMembershipsWithProfiles`/`MembershipRow`/`ProfileRow` are deliberately narrow, built only for name resolution, so this is its own query rather than a forced reuse), **Documents** (reuses `document-backup.ts:getAllBarnDocuments` directly, flattened to one sheet with an Owner Type Horse/Member column), and **All Transactions** (`transactions.ts:getTransactionRows(barnId, ALL_TRANSACTION_KINDS)`, all 6 kinds, no date filter — the barn's full money ledger in one place, kept *in addition to* the collected/payment-status columns folded into Lessons/Agreement Charges, not instead of them;
`membershipId`/`horseId` resolved to names, and #1218 dropped the sheet's former `lessonId`/`lessonRiderId`/`agreementChargeId`/`expenseId` columns — raw UUIDs appearing nowhere else in the workbook, so they cross-referenced nothing a reader could act on.
Amounts are written **signed as the ledger stores them**, i.e. `instructor_payout`/`expense` stay negative rather than going through `transactions.ts:positiveAmount` (#1218) — the column then sums to the barn's actual net, and any future negative-direction kind is covered without an enumerated list here).
Every `TIMESTAMPTZ` column is rendered in the barn's own local time rather than left as raw UTC.
This used to be a deliberate exception to the app's general "instants render viewer-local" convention; #1222 deleted that convention, so the export is now simply doing what every other surface does.
Each such column is emitted as a real `Date` cell (#1218, so Excel can apply a date format instead of storing a bare string).
The five sourced from a genuine `TIMESTAMPTZ` go through the private `barnLocalCell(instant, timezone)` = `new Date(instantToLocalWallClock(instant, timezone) + 'Z')`: **UTC-anchored barn wall clock**, not the real instant.
Excel serials carry no timezone and `exceljs` derives one from `Date#getTime`, so anchoring the barn's wall-clock digits to UTC is what keeps the rendered value identical on every recipient's machine — handing over the true instant, or using `barn-timezone.ts:wallClockToInstant`, would make the rendered value depend on the recipient's own machine, which is exactly what this export avoids.
Six sheets carry one such column, always positioned first (Horses `created_at`, Lessons `lesson_at`, Horse Expenses, Members `created_at`, Documents `created_at`, All Transactions `occurred_at`) and named by what the date *is*: the three `created_at` ones say **Date/Time Added** (Horses, Members, Documents), the three recording when the thing itself happened stay on plain **Date/Time** (Lessons, Horse Expenses, All Transactions).
The remaining two sheets lead with the `DATE`-only column they already had (Agreements' **Start Date**, Agreement Charges' **Period**), so every sheet in the workbook opens with its own date.
One of the six, Horse Expenses, collapses `appointments.expense_date` + `expense_time` into that one cell without calling `barnLocalCell` at all — those two columns are already barn-local digits rather than an instant, so `getExpensesSheet` anchors them to UTC inline and skips the conversion step, and carries a non-column `dateOnly` flag for a row whose `expense_time` is `NULL`, which the workbook builder uses to override just that cell's number format to date-only so a spontaneous appointment doesn't display a fabricated `12:00 AM`.
Remaining `DATE`-only columns (`agreement_charges.period`, a document's `reminder_date`, an agreement's `start_date`) are written as-is, no conversion and no format.
An unresolved name anywhere falls back to `'Unknown Horse'`/`'Unknown Member'` (a lesson with no instructor gets `'No Instructor'` instead, since that's a valid state, not a resolution failure).
`buildBarnDataWorkbook(data)` — pure, no I/O: builds an `exceljs` `Workbook`, one worksheet per row group, via a small private `addSheet` helper that collapses the same repeated lines and (#1218) also applies each column's optional `numFmt` (`'mm/dd/yyyy hh:mm AM/PM'` for a date column, `'"$"#,##0.00'` for every dollar column) and auto-sizes each column to the widest of its header and its values, capped at 60 characters so one long Notes cell can't push the sheet off screen.
A formatted value is measured at its *rendered* text rather than its `String()` form, in both directions: a `Date` at `DATETIME_FMT`'s width (`String(date)` is far longer than the digits Excel renders), and a money value at its `en-US` currency text (`String(45)` is *shorter* than the `$45.00` Excel renders, and a 3-character `Fee` header would otherwise leave the column narrow enough that Excel shows `####`).
The fold is a `reduce`, not a `Math.max` spread, so the unbounded All Transactions sheet can't exceed the engine's argument limit and fail the export.
`addSheet` also (#1218) sorts every sheet **descending by its own first column** via the private `sortByFirstColumn` — newest-first on all eight, driven off `columns[0].key` rather than a per-call-site sort key, so a sheet added later inherits the ordering by construction.
Its comparator uses `<`/`>` rather than dispatching on type, which covers the `Date`-valued columns and the ISO `YYYY-MM-DD` string ones (Start Date, Period) in one path since lexical order is already chronological there, and subtracts the two boolean comparisons instead of branching on them so there's no unreachable third case.
`addSheet` returns `{ sheet, rows }` rather than just the worksheet **because** of this sort: Horse Expenses' per-cell date-only format override indexes rows positionally, so it must walk the sorted array actually written to the sheet, not the caller's original one.
The date format is deliberately **zero-padded** and its column **left-justified** (keyed off the column carrying `DATETIME_FMT`, since that is what makes a column a date column): every rendered date is then exactly 10 characters starting at the same x, which is what makes Horse Expenses legible where date-only and date+time rows interleave — under the unpadded `m/d/yyyy` the dates shifted row to row, and under Excel's right-aligned default for dates a date-only row lined its date up against a timed row's *time*.
Finally `addSheet` styles row 1 — **bold at the default font size**, `height` 30 (2× exceljs's 15-point default), vertically centered — so the header reads as a header rather than as another data row.
The size stays default on purpose: column widths are denominated in the default font's character width, so a larger header font renders wider than `cellWidth`'s budget and clips the longest headers (#1218 shipped 12pt and had to walk it back).
`buildBarnDataBackupBuffer(barnId, timezone, client?)` — orchestrates `getBarnBackupData` + `buildBarnDataWorkbook` + `workbook.xlsx.writeBuffer()`, mirroring `document-backup.ts:buildDocumentsBackupZip`'s fetch → pure-build → orchestrate shape.
Unlike the documents zip, there is no "nothing to export" `null` case — a barn always has at least one `barn_memberships` row (its own manager), so the Members sheet (and therefore the export as a whole) is never genuinely empty.
