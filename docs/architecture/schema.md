# DB schema

All tables are in the `public` schema with RLS enabled.

Migration history through v2.0.2 was squashed (#657) into a 3-file baseline (`supabase/migrations/20260629004610_baseline_schema.sql`, `..._baseline_functions.sql`, `..._baseline_rls.sql`); the original files are kept for reference at `supabase/migrations_archive/`. `release/release-3`'s own accumulated migrations were likewise squashed (#658) into a 4-file set, then squashed a second time (#972) once 6 more fix migrations (#935/#936/#937/#941/#955/#969) landed on top of it during manual QA — the current, final release-3 4-file set is `supabase/migrations/20260716005941_release3_schema.sql`, `..._release3_backfills.sql`, `..._release3_functions.sql`, `..._release3_rls.sql` — a delta on top of the untouched #657 baseline rather than a from-scratch snapshot, since these tables carry real pre-existing data. The #658 4-file set was deleted outright (not archived — it only lived one day); the 6 post-#658 fix migrations are archived at `supabase/migrations_archive/`, same convention as everything before them.

An `expense` row's `amount` is stored **negative** (an outflow), matching the signed-ledger convention `instructor_payout` also uses, so a future `SUM(amount)` nets correctly — DAL reads flip the sign back to the positive magnitude callers already expect. All four composite FKs use the column-list `ON DELETE SET NULL (<col>)` form (Postgres 15+) rather than a bare `ON DELETE SET NULL`, since a composite FK's default `SET NULL` would null every FK column including the `NOT NULL` `barn_id` — same pattern as `lessons_barn_id_instructor_id_fkey`; this lets the money record outlive the deletion of a membership, horse, lesson, lesson participation, agreement charge, or expense row, matching those tables' own existing `ON DELETE SET NULL`/soft-delete conventions. `lesson_riders` gained a `UNIQUE(barn_id, id)` constraint in this same migration (it was the only one of the four source tables missing it) so `lesson_rider_id` could use the same composite-FK pattern as `lesson_id`/`agreement_charge_id`/`expense_id`. RLS grants `SELECT` to `auth_is_barn_manager` only; `INSERT`/`UPDATE`/`DELETE` are explicitly revoked from `authenticated` (baseline's `ALTER DEFAULT PRIVILEGES` would otherwise auto-grant them) — every write goes through `SECURITY DEFINER` RPCs, mirroring how `create_managed_member` etc. already write to RLS-restricted tables regardless of the caller's own table grants. |
