# Finances routes

## `/barn/[slug]/finances`

**Roles:** manager

Three `AccordionSection`s since #1550 — **Outstanding Income**, **Outstanding Expenses**, **Monthly Breakdown** — replacing five flat sibling blocks that competed for the same weight (raised by the 2026-08-16 pre-release run: the page read as one undifferentiated wall).
Native `<details>`, so the open/shut state survives a server round-trip with no client boundary and works pre-hydration; each `defaultOpen`s on having content and stays shut when it doesn't, and both Outstanding sections now render **unconditionally** rather than disappearing, so the page keeps one shape whatever the data.
Each carries a `hint` — `None`/`{n} unpaid`, `None`/`{n} to resolve`, and the month label — as the collapsed row's payload preview.
The month pager and the five tab pills moved **inside** Monthly Breakdown, the only section they ever scoped; the `<hr>` separating the pills from the pager and Pending income line above them moved with it and **stays** — the accordion's card border wraps the whole section, so it separates that section from its neighbours and nothing within it, which is why #1550 first dropping the rule (and `should_render_separator_before_tab_bar` with it) was a review finding rather than a simplification. The section-level amber tint did go: it only ever reached the label `<p>` that is now the accordion's own zinc `<h2>` — the amber that carries the signal is the bold total, untouched.
Each `InfoPopover` sits beside the figure it explains rather than in the header's `headerExtra` slot: a 44px control there forces `pr-32` on the `<summary>`, which crowds the title and hint out of a 390px viewport.

**Outstanding Income** section (renamed from "Outstanding" by #940, no behavior change — all-time past unpaid lessons with non-zero fee, merged with unpaid agreement charges whose `period` is before the first of the current month and uncollected rider late-cancellation fees (#831, `getOutstandingCancellationFees`), via `mergeOutstandingItems` — inline payment-type dropdown via `OutstandingTable` Client Component with a Type column (Lesson/Lease/Boarding/Cancellation Fee) routing to `updatePaymentTypeAction`, `updateChargePaymentTypeAction`, or `updateCancellationFeePaymentTypeAction`, plus a "View all outstanding" link to `/barn/[slug]/finances/outstanding`) is the first of the three sections, and collapses rather than disappearing when there are no outstanding items (#1550 — it was hidden entirely before) — decoupled from outstanding expenses (#872, #940), which get their own independent section (see below), rather than a row type squeezed into this table: an expense has no rider/instructor and no known fee yet, so it doesn't share `OutstandingItem`'s shape or its "pick a payment type, it auto-saves" interaction.
A separate **Outstanding Expenses** section (renamed from "Needs an amount" and broadened by #940 — a bold amber total above the list summing known amounts only, and an `InfoPopover` beside it explaining the inclusion criteria; `getOutstandingExpenses(barn.id, barn.timezone)`, collapsed when empty since #1550, which also moved that amber off the whole section onto the total and gated it on `outstandingExpenses.length > 0` rather than the total being non-zero — an entry with no amount yet still needs attention and contributes $0, but an amber $0.00 on a section with nothing in it would be a false alarm) lists each outstanding expense (missing an amount, missing a payment type, or both, and past its due datetime) as a single line — `"{date} — {recipient} — {expense type}"` — linking straight to `/barn/[slug]/expenses/[id]`, where the existing Amount + Payment Type fields resolve it; no dedicated resolve action or inline form.
Inside **Monthly Breakdown** (always `defaultOpen` — unlike the two above it always has content, a table or the `EmptyState` standing in for one), top to bottom: `←`/`→` month navigation;
`?month=YYYY-MM` selects month (defaults to current, clamped to barn creation date) — parsing/clamping and the prev/next month URLs come from `resolveFinancesMonth` (`src/lib/finances-month.ts`, shared with the four drill-down pages, which previously imported it cross-page from the finances page module), and links re-emit the selected month via its sibling `formatMonthParam`; both "current" and the barn-creation floor are resolved in the **barn's** month via `barnToday`/`barnDay` (#1360 — the module read the server host's UTC month, which rolls over 4–10 hours early for every `BARN_TIMEZONES` zone, defaulting the page to next month's empty window in that window; same defect #1309 fixed one call further down), which is also what took the module off the `eslint.config.mjs` host-zone fence's exemption list;
a single **Pending income** line (only shown for the current month;
this month's still-upcoming lessons whose fee is uncollected, summed net of each lesson's own snapshotted instructor cut, plus unpaid — `payment_type IS NULL` — lease/boarding charges whose `period` is the current barn month or later (`getFinancialSummary`'s two future-only pending rules, which keep any past-due unpaid item out of this line — see [`dal/lesson-finances.md`](../dal/lesson-finances.md)); own `InfoPopover`) is all that remains above the pill switcher — **#971 removed** the three `SummaryStatCard`s (Gross Income / Total Expenses / Net Income) that used to sit above it, since "Gross"/"Net" meant genuinely different things in different breakdown tables below (some net-of-cut, some not) and the cards' own numbers didn't reconcile with any one table;
that ambiguity is what #971 as a whole resolves.
Pill-style tab switcher (`?tab=horse|tier|rider|trainer|recipient`, defaults to `horse`) with five views.
**#971 unifies all five around one model**: every table shows **Gross | Expenses | Net** (`—` for a table with no concept of a column, e.g. By Paid To's Gross/Net, By Rider's Expenses), with **Net = Gross − Expenses always** (never computed independently) — both barn-wide and per-row.
`Gross` = collected `transactions.amount` for positive-sign kinds (`lesson_fee`, `rider_cancellation_fee`, `lease_charge`, `board_charge`) in the month range; `Expenses` = collected `instructor_payout` rows plus every `expense`-kind row with a known amount in the range (`expense-finances.ts`'s `fetchExpenseTransactionsInRange` doesn't gate on `collected` the way the lesson/instructor-payout side does, so an expense with an amount entered but no payment type yet still counts here, matching its pre-existing appearance in the separate Outstanding Expenses section); this makes barn-wide Net a real bottom-line figure that can go deeply negative in an expense-heavy month, not "net of instructor cut only."
Each table ends in a shared `<tfoot>` (`ReconciliationFoot.tsx`) with four rows, in order — **Subtotal** (this table's own attributable rows), **Unattributed** (`InfoPopover`-explained;
genuine data gaps — most commonly an `expense`-kind `transactions` row whose owning `appointments` record was deleted after being marked paid, per `deleteExpense`'s default `deleteCollectedTransactions=false`, so the cost survives in `getExpenseFinancialSummary`'s `totalExpenses` but drops out of every per-horse/per-recipient `breakdown` — previously silently missing from By Horse/By Paid To entirely, now surfaced here instead;
rendered above Outside this view since it's a gap in *this* table's own data, a more direct concern than money that's real but structurally belongs elsewhere), **Outside this view** (`InfoPopover`-explained;
derived as `barnTotal − Subtotal − Unattributed`, e.g. lease/boarding income has no lesson tier so it's By Tier's Gross-Outside;
horse expenses have no instructor so they're By Instructor's Expenses-Outside), and **Total** (bold, `Subtotal + Outside + Unattributed`, identical across all five tabs for a given column) — the Expenses column's `ValueCell` passes `forceParens` (with a same-as-`ByTierTable` zero-guard rendering exact zero as `—` rather than the `-0` formatting artifact `($0.00)`), so every bucket's Expenses figure renders in accounting parens consistently, not just each table's own body rows — computed via `src/lib/finances-reconciliation.ts`'s `buildReconciliationColumn(total, subtotal, unattributed)` (deriving `outside`) and `deriveNetColumn(gross, expenses)` (subtracting field-by-field: `subtotal`, `outside`, `unattributed`, and `total` each independently).
This footer is what the former synthetic body rows (`Non-lesson income`, `No horse`, `No rider`, `No instructor`) were replaced by — their totals now fold into a table's Outside-this-view or Unattributed bucket instead of appearing as an unlinked `<tbody>` row.
All five tables keep #945's client-side-only sortable column headers — a shared `useSortableRows` hook (`src/app/barn/[slug]/(protected)/finances/useSortableRows.ts`) plus a single `SortableTh` header cell used for every column on every table (#971 consolidation — previously By Rider's Expenses and By Paid To's Gross/Net used ad hoc `<Th>`+`InfoPopover>` markup instead): when `sortKey`/`onSort` are supplied it wraps the shared `<Th>` with a clickable button, `aria-sort`, and a ▲/▼ directional indicator;
when omitted it renders the label as plain non-interactive text with no `aria-sort` (By Rider's Expenses, By Paid To's Gross/Net);
either way an optional `infoText` prop renders an `InfoPopover` as a **sibling** of the label/button — not nested inside it, so tapping the info icon never triggers a sort — both living in one `inline-flex` row so the icon can never wrap onto its own line below the label (a block-level `flex` button was the original bug) — each table is its own small Client Component (`ByHorseTable.tsx`/`ByTierTable.tsx`/`ByRiderTable.tsx`/`ByInstructorTable.tsx`/`ByPaidToTable.tsx`) rather than inline JSX in the (Server Component) page, since sort state needs a client boundary;
no server round-trip, no URL param;
default sort is the name column ascending for all five (the synthetic-row-derived footer is structurally outside `<tbody>` so it's never part of the sort), clicking a column sorts it ascending first, clicking the active column again flips direction.
**By Horse** (Horse/Gross/Expenses/Net — row set is the *union* of horses with lesson/agreement income that month and horses with expenses that month, via `getExpenseFinancialSummary`'s per-horse `breakdown`; a horse present on only one side still gets a row — an expense-only horse (e.g. injured, vet bills only) shows `$0.00` Gross and surfaces with a negative Net, while an income-only horse's Expenses cell renders `—`, the same render-exact-zero-as-`—` convention as the reconciliation footer's Expenses cells; `Gross` comes from `getHorseIncomeSummary`'s now-gross `totalIncome` (#971, `splitsGrossFee`), `computeHorseNetIncome` derives `net = gross − expenses`).
**By Tier** (tier name, **Gross**/**Expenses**(the tier's own summed instructor cut, `—` at zero)/**Net** — #971 dropped both the `Lessons` count column and the `Price` column;
every active barn tier still appears even with zero paid lessons that month, #771, **except** the tab now gates on real activity rather than row count — `page.tsx`'s `tierHasActivity` checks whether any tier row has a non-zero `subtotal`/`instructorCut`, since #771's own per-active-tier `$0` backfill means `breakdown.length` is never 0 for a barn with any active tier, **or** whether `tierGross.outside` is non-zero (a review-follow-up fix — a boarding/lease-only month with zero paid lessons has an all-zero `tierRows`, but real charge income still exists via the `NON_LESSON_INCOME_LABEL` row `tierRows` excludes, and that money must still show up reconciled in the footer's Outside-this-view row rather than being hidden behind an `EmptyState`);
a month where every tier collected nothing AND no charges were collected either renders `EmptyState` instead of a table full of `$0.00` rows).
**By Rider** (rider name — underlined link — **Gross** (#971, now exposed via `RIDER_INCOME_DESCRIPTOR`'s `splitsGrossFee`, previously this tab had no Gross column at all), **Expenses** always `—` (no rider-level expense concept — rendered via `SortableTh`'s own non-sortable mode, no `sortKey`/`onSort` passed, since sorting a constant column is meaningless), **Net** reuses the Gross column's sort key since the two are always numerically equal).
**By Instructor** (trainer full name — underlined link to that trainer's drill-down — **Gross** (that trainer's raw, pre-cut lesson fees), **Expenses** (renamed from "Instructor Cut", Gross minus Net, `—` when Gross is `—`), **Net**).
**By Paid To** (#949 — recipient name — underlined link, since `appointments.recipient` is free text with no id anywhere in the schema — **Gross**/**Net** always `—` (a recipient has no revenue concept), **Expenses** (renamed from "Expense Amount", #971) via `getRecipientExpenseSummary`).
Every tab's default sort re-sorts by name/recipient ascending on load regardless of the DAL's own sort order;
negative net figures (e.g. a comped lesson after the cut, or a horse's negative Net) render accounting-style via the shared `formatCurrency` helper (`src/lib/format-currency.ts`) rather than a leading minus sign — and date cells across the finances pages (both Outstanding tables, the three drill-downs) plus the dashboard's `DocumentRemindersSection` render via the shared `formatShortDate`/`formatShortDateOnly` helpers (`src/lib/format-date.ts`), consolidated from per-module private copies;
the By Horse/By Rider/By Instructor name cells are underlined links (#771 — persistent, not hover-only, matching the drill-down pages' own date-link styling) to their respective drill-down pages (`finances/horses/[id]`, `finances/riders/[id]`, `finances/trainers/[id]`), which show the same pre-cut fee and split amounts as the tab they were reached from (#1156 — the By Horse/By Rider drill-downs were still net-of-cut after #971 moved only the summaries to gross, which is why the two pages' figures didn't reconcile;
the By Instructor drill-down stays net-of-cut, where that cut is the view's subject), also via `formatCurrency`;
the drill-down pages otherwise remain unaffected by #971 (out of scope — no reconciliation footer or Gross/Expenses/Net unification on them);
the By Paid To recipient name cells are likewise underlined links (#949) to `finances/expenses/[recipient]`

## `/barn/[slug]/finances/outstanding`

**Roles:** All active members

Read-only list of outstanding items for the calling user's role (lessons merged with agreement charges and rider cancellation fees via `mergeOutstandingItems`, #831, with a Type column); manager sees all barn outstanding, trainer sees own lessons only (instructor_id filter; not a party to agreements) plus cancellation fees for lessons they instruct, rider sees enrolled lessons plus their own outstanding leases/boarding and own cancellation fees; each lesson row and each cancellation-fee row (linked via its parent lesson) links to the lesson detail page; each charge (lease/board) row links to its agreement detail page for a manager viewer only (#931 — `OutstandingCharge.agreementId`, resolved from `agreement_charges.agreement_id`; `/barn/[slug]/agreements/[id]` is manager-only, so a trainer/rider's own charge row renders as plain unlinked text, mirroring the member detail page's `ActiveAgreements` `linkable` gating, #772)

## `/barn/[slug]/finances/horses/[id]`

**Roles:** manager

Per-horse drill-down for a given month (`?month=YYYY-MM`, defaults to current); one combined table of the horse's paid lessons (full fee, horse count, split amount, linking to the lesson), paid agreement charges (full amount, no split, linking to the agreement), and expenses (amount and split in accounting-parens format, linking to the expense), each row tagged with a **Type** column (Lesson/Lease/Boarding/Expense) and all rows ordered by date ascending; bottom **Net** row = lesson splits + charge fees − expense splits, matching this horse's Net on the "By Horse" tab; linked from the By Horse tab with month param preserved

## `/barn/[slug]/finances/riders/[id]`

**Roles:** manager

Per-rider income drill-down for a given month (`?month=YYYY-MM`, defaults to current); reworked in #771 to match the By-Horse combined-table pattern above — one table of the rider's paid lessons (full fee, rider count, split amount, linking to the lesson) and paid agreement charges (full amount, no split, linking to the agreement), each row tagged with a **Type** column (Lesson/Lease/Boarding) and ordered by date ascending, replacing the prior two-table "Leases & Boarding" layout; bottom **Total** row matches the "By Rider" summary on the finances page; linked from the By Rider tab with month param preserved

## `/barn/[slug]/finances/trainers/[id]`

**Roles:** manager

Per-trainer income drill-down for a given month (`?month=YYYY-MM`, defaults to current), added in #771 following the same combined-table/Type-column pattern as the horse/rider drill-downs above; one table of the trainer's paid lessons (lesson date linking to the lesson detail, Type always "Lesson", fee net of that lesson's own snapshotted instructor cut — no split, since `lessons.instructor_id` is a single column rather than a junction table like `lesson_riders`/`lesson_horses`), ordered by date ascending; no charge rows — agreements have no instructor; bottom **Total** row matches that trainer's **Net** on the finances page's By Instructor tab (the tab's columns have been Gross/Expenses/Net since the #945/#971 renames, and this net-of-cut total is its Net figure); linked from the By Instructor tab with month param preserved

## `/barn/[slug]/finances/expenses/[recipient]`

**Roles:** manager

Per-recipient expense drill-down for a given month (`?month=YYYY-MM`, defaults to current), added in #949; `[recipient]` is the raw recipient string itself (URL-encoded by the linking By Paid To tab and explicitly `decodeURIComponent`-decoded by the page — Next hands the route param over still percent-encoded, and a #949 follow-up commit added the decode after the still-encoded name matched no stored recipient and the page showed the raw encoded string with no activity), not a resolved entity id, since `appointments.recipient` is free text with no id anywhere in the schema; one table of that recipient's expenses that month (Date — linking to the expense's edit page, Type — the expense's `expense_type`, Amount), ordered by date ascending, mirroring the By Trainer drill-down's flat (unsplit) shape rather than the By Horse/Rider drill-downs' split-across-participants shape, since a recipient is 1:1 with each of its expenses; bottom **Total** row matches the "By Paid To" summary on the finances page; linked from the By Paid To tab with month param preserved
