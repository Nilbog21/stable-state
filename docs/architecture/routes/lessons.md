# Lessons routes

## `/barn/[slug]/lessons`

**Roles:** All active members

Lessons split at 7-day cutoff: recent shown immediately, older behind `OlderLessonsToggle`; each lesson renders as a full-width `Card` link to its detail page (`LessonListItem`, matching the Agreements list pattern) — no Cancel affordance lives on this list (#825, consolidated onto the lesson detail page's header, see below); `LessonListItem` no longer takes a `currentMembershipId` prop, only `viewerMembershipId` (still used to resolve the viewing rider's own row for the badge below); cancelled lessons show a "Cancelled" badge, and a rider whose own participation is cancelled (but the lesson itself isn't) sees the same badge on their own row; a normal lesson's rider name is shown to manager/trainer only — hidden for the rider role, since on their own self-scoped list it's always their own name (#767); role-aware filter bar above the list, mobile-wrapping (`flex-wrap`, no horizontal scroll) — manager/trainer see `My Lessons | All | By Instructor | By Rider | By Horse | By Tier` (`My Lessons`, filtering to `instructor_id === own membership id`, is the default for trainer only when no `?filter=` param is present — manager isn't guaranteed to be an instructor, so manager defaults to `All`, #1025); rider sees `All | By Instructor | By Horse | By Tier` (no `My Lessons` or `By Rider` — their list is already self-scoped), defaulting to `All`; selecting `By Instructor`/`By Horse`/`By Tier` (and, for manager/trainer, `By Rider`) reveals a second row of specific people/horses/tier names — trainer sees all barn instructors, not just themselves; `By Tier` (#948) filters to lessons matching the picked `tier_name` exactly, options built from the distinct tier names present across the caller's own already-role-scoped lesson list (not a barn-wide tier fetch), so a tier with zero lessons visible to this caller never appears as a filter option; active filter persists in URL params (`?filter=mine|all|trainer|rider|horse|tier&id=<uuid>`, unchanged despite the "By Instructor" label — a tier filter's `id` is the URL-encoded tier name, not a UUID); the `rider` filter's application (not just its pill) stays gated to manager/trainer server-side, matching every other role-restricted pill; the filter bar itself is hidden entirely when the barn has zero lessons at all (nothing to filter), but stays visible whenever the *current filter* yields zero results despite the barn having lessons elsewhere — that case shows "No lessons match this filter" instead of the barn-empty "No lessons yet" copy

## `/barn/[slug]/lessons/new`

**Roles:** manager, trainer

A "Recurring (weekly)" checkbox atomically creates a `lesson_series` template row alongside the first lesson (via `createLessonSeries`) instead of a plain one-off lesson.
`LessonForm` also snapshots `instructor_cut` into a hidden field (#776) for display/back-compat, but the value that actually lands in the DB is re-derived server-side by the RPC from the selected tier's rate, or `barns.default_instructor_cut` for a Custom lesson — not user-editable here, only on the tier itself, and not trusted from the client even via a direct RPC call.
`LessonForm`'s horse picker (shared with the edit form below) re-fetches projected exhaustion for exactly the horse IDs it's rendering (its `horses` prop, not a barn-wide fetch) via `getProjectedExhaustionForBarn` whenever the lesson date/hour changes, and shows an `ExhaustionBar` under each horse with a live ghost segment reflecting that horse's currently selected exertion level — no bar shown until the data fetched for the currently-selected date has resolved (so changing the date doesn't briefly display the previous date's numbers), no bar shown for an inactive or unavailable horse the lesson isn't currently assigned to (#766 — the fetch still requests exhaustion for those horses, only the bar is suppressed; a horse that's still checked on the lesson being edited keeps its bar regardless of active/available status, preserving #426's original fix), and no bar shown once the lesson's date/hour is in the past (#766, compared against the current hour rather than the exact minute, so "now" never itself counts as past); the picker list itself is sorted checked horses first, then available, then inactive/unavailable last, each bucket ordered least-to-most exhausted by that horse's own fetched exhaustion total (#766); the edit form binds the same action with `p_exclude_lesson_id` set to the lesson being edited so it doesn't count against its own horses, and passes the horse IDs of `horsesForForm` (including any horse deactivated after being assigned to this lesson) — that horse stays checked by default (from `initialLesson.lesson_horses`), so it's still fetched, sorted first, and keeps its bar; only sorts into the inactive/unavailable bucket (and loses its bar) if manually unchecked; the horse-picker fieldset legend reads "Horse" for a **normal** lesson (exactly one required) vs. "Horses (select at least one)" for a **group** lesson; the Payment Type field is hidden entirely whenever the fee is `0` — `payment_type` is simply omitted from the submission (parses to `null`/unpaid), which is sufficient to read as "automatically collected" since `getOutstandingLessons`'s `fee ≠ 0` filter already excludes `$0` lessons from Outstanding regardless of `payment_type`

## `/barn/[slug]/lessons/[id]`

**Roles:** All active members

`notFound()` if the lesson doesn't exist, is in a different barn, or (rider only) the caller has no `lesson_riders` entry on it — defense-in-depth on top of the enrollment-scoped RLS; Edit link visible to managers and to the instructing trainer only (a trainer viewing a lesson they don't instruct doesn't see it, since trainers can now see every barn lesson on the list page, not just their own); the page is now purely read-only for every note field (#797) — Horse Notes, Rider Notes, Private Notes, a rider's own "Your Notes", and (whole-lesson and per-rider) Cancellation Notes are all hidden entirely (label + text) whenever the underlying value is null/empty, for every role, rather than rendering an empty label or a "—" placeholder; trainer/manager see non-empty `horse_notes` inline under each horse entry and non-empty `rider_notes`+`private_notes` (visually distinguished) inline under each rider entry; each horse entry's exertion rating was originally manager/trainer-only (#937, closing a gap `getLessonById`'s `lesson_horses` select left open — it no longer selects `exertion_level` directly for any role, not just hiding it in the UI for a rider caller); `exertion_level` has no column-level GRANT restriction on `lesson_horses` for `authenticated`, so a per-role select string alone can't stop a rider's own session from reading it directly via PostgREST (a #937 review follow-up caught this — the initial fix only closed the app's own code path); `getLessonById` instead resolves it via `get_lesson_horse_exertion_levels` (see [`rpc.md`](../rpc.md)), a `SECURITY DEFINER` RPC gated the same way `get_horse_exertion_summary`/`get_horse_projected_exhaustion` were, called for every role and merged onto each `lesson_horses` row by `horse_id` — since #999, the RPC itself also returns a row for a rider with `lesson_read_privileges=true` on that specific horse, so a privileged rider-owner now sees their own horse's exertion here too, without the barn-wide access `get_horse_exertion_summary` still restricts to manager/trainer; rider sees own non-empty `rider_notes` read-only; a red "Cancelled" badge appears next to the lesson type/Jumping badges whenever `lesson.cancelled_at` is set, independent of whether `lesson.cancellation_notes` has content — `lesson.cancelled_at` can be set either directly (whole-lesson cancel) or by cascade from `cancel_rider_participation` (see `cancel_rider_participation` in [`rpc.md`](../rpc.md)) when the last active rider is cancelled; the "Cancellation Notes" row itself is keyed off `lesson.cancellation_notes` being non-empty (decoupled from `cancelled_at`) and is always read-only now — editing moved to the Edit Lesson form's Notes section (see below); each rider row shows only a read-only "Cancelled" badge when that rider's participation is cancelled (#825 — the per-row "Cancel" link that used to sit next to a non-cancelled rider's name, linking to `/barn/[slug]/lessons/[id]/cancel-rider/[rider membership id]`, was removed from this list entirely) plus that rider's `cancellation_notes` when non-empty, read-only text visible to every role regardless of who entered it or whose row it's on (unlike `rider_notes`/`private_notes`, which stay own-row/staff-only masked — a cancellation reason is administrative context for the whole lesson, not private) — the DAL never nulls `lesson_riders.cancellation_notes` for the rider role (#741 follow-up); rider sees the same badge for their own row only, which stays visible even when that rider has no notes to show (only the notes label/text hides, never the badge); in place of every removed per-row link, the header now shows a single "Cancel" button (#825) next to Edit/Delete: visible to the manager or instructing trainer (same eligibility as the whole-lesson cancel below) linking to `/barn/[slug]/lessons/[id]/cancel`, or to the enrolled rider for their own still-active participation (same eligibility, plus their own `lesson_riders.cancelled_at IS NULL`) linking to `/barn/[slug]/lessons/[id]/cancel-rider/[own membership id]` — manager also sees a Delete entry point next to Cancel/Edit, reachable regardless of lesson state (past/future, paid/unpaid, already cancelled) — hard-deletes the lesson via `deleteLessonAction`/`deleteLesson`, unlike Cancel this leaves no record (beyond `transactions` rows, see below) and fires no notifications; when the lesson is ledger-uncollected (`lesson.fee !== 0 && lesson.payment_type === null` — a $0 fee is always ledger-collected regardless of `payment_type`, per `sync_lesson_transactions`'s own `v_collected` formula, corrected in a #827 review follow-up from checking `payment_type === null` alone), this is still the bare `DeleteLessonButton` (`window.confirm`-gated, mirrors `StopSeriesButton`) straight to `deleteLessonAction`; when ledger-collected, it's instead a link to `/barn/[slug]/lessons/[id]/delete` (#827) — a `DeleteLessonButton` confirm dialog can't show the collected-fee tradeoff a `transactions`-aware delete now has; above the card, a `HorseStatusBanner` (#848, shared with the edit page below) renders whenever `getHorseAttentionReasons` (`src/lib/lesson-authorization.ts`) returns a non-empty list — the same future/non-cancelled/inactive-or-unavailable condition #847's badge uses, evaluated from this page's own already-fetched `lesson.lesson_horses[].horses.is_active`/`is_available`/`unavailability_reason` (no extra query) — naming each affected horse and why ("Buttercup is inactive" / "Rocky is unavailable: lame — resting per vet"); purely informational, visible to every role, never blocks Edit/Cancel/Delete; (#999) a rider not enrolled in this lesson (no `lesson_riders` row) no longer always 404s — `isPrivilegedViewer` (`role === 'rider' && lesson.lesson_horses.some((lh) => lh.exertion_level !== undefined)`, i.e. `get_lesson_horse_exertion_levels` returned a row for at least one of this lesson's horses, meaning the caller holds `lesson_read_privileges` on it) lets that rider through instead of hitting `notFound()`; a privileged non-enrolled rider sees their privileged horse's `horse_notes` and exertion rating (same rendering as manager/trainer, keyed off `exertion_level !== undefined` rather than `canSeeNotes`) but `canSeeNotes` stays `role === 'trainer' || role === 'manager'` only, so every other rider's `rider_notes`/`private_notes` remain hidden from this viewer the same as from any other rider

## `/barn/[slug]/lessons/[id]/delete`

**Roles:** manager

Delete confirmation page (#827, mirrors `/barn/[slug]/expenses/[id]/delete`), reached only from the lesson detail page's Delete entry point when the lesson is ledger-collected (`lesson.fee === 0 || lesson.payment_type !== null`); `notFound()` if the lesson doesn't exist; shows the collected `$fee` amount and an unchecked-by-default "Also delete the collected $fee record from Finances" checkbox (`alsoDeleteTransactions`) — unchecked (the default) keeps the `lesson_fee`/`instructor_payout` `transactions` rows after the lesson is gone (they survive via the table's own `ON DELETE SET NULL (lesson_id)` FK), checked opts into deleting them too; submits to `deleteLessonAction`, which reads the checkbox and forwards it to `deleteLesson`'s `deleteCollectedTransactions` param

## `/barn/[slug]/lessons/[id]/edit`

**Roles:** manager, trainer

Pre-filled edit form; instructor field hidden entirely for trainers (value still submitted/locked server-side, DB enforces via RLS) instead of shown read-only; group→normal downgrade shows warning and requires manager to select one rider/horse to keep; updates are atomic via `update_lesson_with_participants` RPC; only managers can add new horses or riders inline; notes editing is embedded inside `LessonForm` via `initialNotes` prop and saved by `updateLessonAction` via the single Save button; when the lesson being edited is already cancelled (`initialLesson.cancelled_at !== null`), the Notes section also gains a Cancellation Notes textarea (#797, replacing the old inline-editable field on the detail page), pre-filled from `initialLesson.cancellation_notes` and persisted by `updateLessonAction` alongside the horse/rider notes writes, under the same manager/instructing-trainer authorization already enforced by this page — not shown at all for a non-cancelled lesson; navigating away with unsaved notes shows a confirmation prompt; when `lesson.series_id` is set and the linked `lesson_series.is_active` is `true`, shows a "This is part of a recurring series" indicator plus a destructive **Stop Recurring Lessons** button (`StopSeriesButton`, confirm dialog, mirrors the agreements page's `EndAgreementButton`) — for a trainer, the button is only rendered when `lesson_series.instructor_id` matches their own membership id, since a lesson's current instructor (gating page access) and its series' original instructor (gating the stop write) can diverge after a manager reassigns the lesson; on submit, `stopLessonSeriesAction` sets `lesson_series.is_active=false` (manager: any series; trainer: only a series where `instructor_id` is their own membership, matching the RLS `lesson_series_update_trainer` policy) without touching any `lessons` rows, then redirects back to this page; below the heading (and above the recurring-series indicator), the same `HorseStatusBanner`/`getHorseAttentionReasons` pair as the detail page above (#848) renders under the identical condition — informational only, doesn't affect Save; `LessonForm` also receives `hasHorseIssue` (#849, `attentionReasons.length > 0`, reusing the same computed value) and OR's it into its existing nav-blocker `shouldWarn` check alongside unpaid/notes/field dirtiness — leaving the page (nav link, browser back, tab close) prompts a confirm dialog even when no form field was touched, and stops prompting once the flagged horse is swapped out and saved, since `attentionReasons` is recomputed fresh from the DB on the next page load

## `/barn/[slug]/lessons/[id]/cancel`

**Roles:** manager, trainer (own lesson only)

Sole entry point is the single "Cancel" button on the Lesson Detail header (#825, replacing the former per-row Cancel link on the Lessons list).
Confirmation form: optional cancellation-notes textarea + destructive "Confirm Cancellation" button; `notFound()` if the lesson doesn't exist, the trainer doesn't own it, or it's ineligible (already cancelled, or past-and-paid); the "Cancelled by Rider" / "Cancelled by Instructor" type radio (`CancelLessonFields`, a Client Component) now always renders, for both **normal** and **group** lessons alike (#825 — previously group lessons showed no radio at all) — for a **normal** lesson (1 rider), cancelling the lesson and cancelling that rider's participation are the same event, so the identical late-fee policy applies (`isLate = cancel_type==='rider' && lesson_at − now() ≤ 24h`); for a **group** lesson, selecting "Cancelled by Instructor" keeps the pre-#825 whole-lesson behavior (always fee-waived, confirmation text lists the count and names of enrolled, not-yet-individually-cancelled riders so the blast radius is visible before confirming), while selecting "Cancelled by Rider" instead reveals a single-select "Rider" fieldset (one radio per still-active enrolled rider, each marked `required`) and swaps the description to a short "select a rider" prompt; when "Cancelled by Rider" is selected on a lesson booked less than 24 hours out (#944, `CancelLessonFields.tsx`, the late-fee window recomputed live client-side against the lesson's actual `lesson_at` rather than snapshotted at page load), an amber note appears — on a normal lesson, warning the rider will be due a late cancellation fee; on a group lesson, warning instead that no late fee is currently charged for group lessons at all, since `sync_rider_cancellation_fee` no-ops for `lesson_type <> 'normal'` (see [`rpc.md`](../rpc.md)) — surfacing that known gap before the manager/trainer confirms rather than leaving it silent; on submit, `cancelLessonAction` reads `cancel_type`/`rider_id` from the form and, only for a **group** lesson with `cancel_type==='rider'` and a non-empty `rider_id`, delegates directly to `cancelRiderParticipationAction` (see below) instead of running its own whole-lesson cancel logic — reusing that action's own eligibility check, RPC call, and notifications rather than duplicating them; otherwise (normal lesson, or group + "Cancelled by Instructor") it proceeds as before: sets `cancelled_at=now()`, saves notes, zeroes `fee`/nulls `payment_type` unless `isLate`, fires `lesson_cancelled` notifications (trainer cancels → barn manager(s) + enrolled riders; manager cancels → instructor + enrolled riders), then redirects to `/barn/[slug]/lessons/[id]` (#825 — changed from the lessons list, matching the new header entry point and `cancelRiderParticipationAction`'s own redirect target)

## `/barn/[slug]/lessons/[id]/cancel-rider/[riderId]`

**Roles:** manager, trainer (own lesson only), rider (self only)

Cancels a single `lesson_riders` row rather than the whole lesson; reachable in the UI only via the rider's own "Cancel" button on the Lesson Detail header (#825 — the manager/instructing-trainer per-row "Cancel" link that used to also point here was removed from the Riders list; a manager/trainer's group-lesson per-rider cancel now goes through the rider picker on `/cancel` above instead) — the route itself, its auth checks, and its own in-page type selector are otherwise unchanged, so it remains directly reachable (and still fully authorized) for a manager or instructing trainer who navigates to it directly.
The rider is fixed by the URL, so there is no in-form rider selector even for group lessons.
`notFound()` if: the lesson doesn't exist, the whole lesson is already cancelled, the trainer doesn't instruct it, `riderId` isn't a rider on the lesson, a rider requests someone else's `riderId`, or the target participation is already cancelled or ineligible (`lesson_at > now()` OR `payment_type IS NULL`).
Manager/trainer see a type selector — "Cancelled by Rider" / "Cancelled by Instructor" — that overrides the fee policy rather than just labeling who acted: the radio defaults to "Cancelled by Instructor" when the acting manager/trainer is the lesson's own instructor (`isInstructorOfLesson`, `src/lib/lesson-authorization.ts`), else "Cancelled by Rider" (matching prior behavior — this is also what a manager sees when they don't instruct the lesson); "Cancelled by Instructor" always waives the fee (`isLate=false`); "Cancelled by Rider" applies the literal 24-hour policy (`isLate = lesson_at − now() ≤ 24h`, i.e. late/no-notice cancellations keep the fee, earlier ones zero it).
A self-cancelling rider always gets the "Cancelled by Rider" policy with no selector shown, and can't spoof the instructor waiver via form data — enforced server-side by the RPC itself, not just the form, since the RPC re-derives `isLate` from the lesson's real `lesson_at` whenever the caller is cancelling their own participation, ignoring whatever `p_is_late` value the client sent.
On submit, `cancelRiderParticipationAction` calls `cancelRiderParticipation`, then fires `rider_participation_cancelled` notifications (a distinct type from whole-lesson `lesson_cancelled`, so the two flows don't collide on the same recipient's notification row) keyed on **actor role** (not the type selected): rider self-cancels → instructor + all active managers; manager/trainer cancels on behalf of a rider → the affected rider (skipped if unclaimed/managed with null `user_id`) + all active managers only when the actor is a trainer; when `cancelRiderParticipation` reports a cascade (this was the last active rider — see `cancel_rider_participation` in [`rpc.md`](../rpc.md)), also fires `lesson_cancelled` notifications using the same recipient rule as `cancelLessonAction` (trainer cancels → managers + riders; manager/rider cancels → instructor + riders); redirects to `/barn/[slug]/lessons/[id]`
