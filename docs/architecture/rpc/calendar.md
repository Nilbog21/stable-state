# Calendar RPCs

`get_calendar_feed(p_token text) RETURNS TABLE(valid boolean, barn_name text, items jsonb)` (#1018) — the sole authorization/data path for the personalized `.ics` calendar Route Handler, which has no session (an external calendar poller can't carry a cookie or run a server action) and so can't rely on RLS at all.
Resolves `p_token` to an active `barn_memberships` row (`calendar_feed_token`, `status = 'active'`) inside the function body, then returns that membership's role-filtered schedule in the same round trip: manager sees every non-cancelled lesson and every `barn_events` row in the barn; trainer sees only lessons where `instructor_id` matches their own membership; rider sees lessons where they have a non-cancelled `lesson_riders` row, plus (mirroring `auth_lesson_has_privileged_horse`, #997) any lesson involving a horse they hold `lesson_read_privileges` on — that helper checks `auth.uid()`, unavailable to this anon-token-authenticated caller, so the equivalent `lesson_horses`/`member_horse_privileges` join is inlined against the resolved membership id instead; `barn_events` visibility for trainer/rider follows `visible_to_roles` the same way the table's own RLS does.
`items` is a `jsonb` array of `{itemType, id, title, startsAt, durationMinutes, notes}` objects — lessons get a synthesized `durationMinutes: 60` (mirrors `schedule.ts`'s `LESSON_DURATION_MINUTES`) plus a compact `title` and a fuller `notes` (rendered as the ICS `DESCRIPTION`), both built from a per-lesson `LATERAL` subquery joining `lesson_riders`/`lesson_horses` to `barn_memberships`/`profiles`/`horses` (#1018 follow-up, `20260724034551_calendar_feed_title_rider_horse.sql`, replacing the original tier-name-only title): `title` is `"Lesson - <rider First L.>, <horse name>"` for a `normal` lesson (a normal lesson always has exactly 1 rider/horse per the `enforce_lesson_participant_counts()` trigger (see [`lessons.md`](lessons.md))) or `"Lesson - Group"` for a `group` lesson, with `" (Jumping)"` appended when `jumping`; `notes` is a newline-joined `Trainer: <name>` (omitted when `instructor_id IS NULL`, mirroring `LessonListItem.tsx`'s own omission of a missing instructor) / `Rider: <name>` / `Horse: <name>` breakdown — the last two labels pluralizing to `Riders: <name, ...>`/`Horses: <name, ...>` when `lesson_type = 'group'` — always listing every rider/horse (not just a count) regardless of viewer role.
Events pass through `title`/`notes` unchanged and `durationMinutes: 0`.
Always returns exactly one row: `valid=false` (with `barn_name=NULL`, `items='[]'`) for an unknown or inactive token, never zero rows — this is what lets the route handler distinguish "bad token" (404) from "valid token, nothing scheduled" (200, empty calendar) from a single call, without a second round trip that would let an anon caller probe token validity and schedule contents separately.
A single function is deliberate: a design with a separate "resolve token" RPC plus a "fetch items" RPC taking raw `barn_id`/`role` params would leave that second RPC anon-reachable with attacker-supplied authorization inputs.
`LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public`; `EXECUTE` revoked from `PUBLIC` and granted to **both** `anon` and `authenticated` — the token itself is the authorization, so the calendar poller's unauthenticated request (using the anon key) must be able to call it.
Used by `getCalendarFeedData` in `calendar-feed.ts`, called from `src/app/calendar.ics/route.ts`.
**#1286 update** (`20260805022307_ordered_calendar_feed_and_exhaustion.sql`): the outer `jsonb_agg` is now `jsonb_agg(item ORDER BY starts_at, item->>'id')`, where `starts_at` is a raw `timestamptz` both CTEs carry alongside their built object — the `UNION ALL` left `items` in planner order before.
Ordering on the column rather than on the rendered `item->>'startsAt'` text is deliberate: the two agree only while every value renders at the same UTC offset, which is a property of the session's `TimeZone` setting rather than of this function.
The `item->>'id'` tiebreak makes a lesson and an event at the same instant deterministic too.
No behavioral effect on subscribers (a calendar client sorts by `DTSTART` itself) — the point is that a diff-based test of the feed now has something stable to assert.
The inner `string_agg`s were already `ORDER BY`ed by name and are unchanged.
**#1640 update**: a third CTE, `appointment_items`, unions `appointments` in — the function shipped before #1148 renamed `horse_expenses`, so vet and farrier visits had never reached a subscribed calendar at all.
Gated on `appointments.shows_on_calendar`, which is what keeps the Insurance and Feed bills sharing that table off a manager's phone (the column's own rationale and backfill are in [`../schema.md`](../schema.md)'s `appointments` row), and on `r.role IN ('manager', 'trainer')`, matching that table's own RLS — riders get no appointment row and no new grant was needed.
`title` is `"<expense_type> — <recipient>"`, reusing the label `schedule.ts` builds for the in-app calendar so the two surfaces cannot drift, or the recipient alone when `expense_type` is still the `'Unspecified'` default; `notes` is the horse list (or `All horses`) newline-joined with the row's own `notes`; `durationMinutes` is 0, matching events.
The CTE **must not join `appointment_costs`**, and this is the load-bearing constraint on any future edit: the function is `SECURITY DEFINER` and bypasses RLS, so that table's manager-only policy — the whole reason #1148 split the money off the appointment — is not enforcing anything here. The SQL is. `checklist-phase4-calendar-feed.spec.ts`'s `the_calendar_feed_carries_no_appointment_amount_anywhere` scans the whole payload for a seeded amount for that reason.
`items` objects gained an optional `allDay`, set only by a time-less appointment. Such a row carries the raw `"YYYY-MM-DD"` digits in `startsAt` rather than an instant, and `ics.ts` renders `DTSTART;VALUE=DATE`/`DTEND;VALUE=DATE` (end = next day) straight from them — round-tripping the day through a real instant shifts it for any subscriber the other side of UTC midnight, which is the bug this shape exists to make unrepresentable. A timed appointment converts through `AT TIME ZONE barns.timezone` like everything else, formatted explicitly rather than left to `timestamptz`'s own text rendering.
The `starts_at` ordering key is a real instant in both cases (`expense_date + COALESCE(expense_time, '00:00:00')` through the barn's zone), so #1286's ordering above still holds across all three CTEs — only the payload's `startsAt` differs in shape.
